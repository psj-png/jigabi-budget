# 지갑이 인계 메모 (2026-11-18)

대학생 가계부 '지갑이': 사기 전에 "이거 사면 이번 기간 내 생활이 어떻게 되는지" 보여주고, 산 뒤엔 남은 날을 다시 짜 준다.
FastAPI + Jinja2(서버 렌더링, JS 최소) + MySQL 8, Docker.

## 먼저 읽을 것
- `CLAUDE.md`: 작업 방식, 코드 스타일, 일정
- `docs/rules.md`: 계산 규칙 R1~R22와 확인용 숫자. 숫자는 전부 이 규칙대로 계산하고, 규칙을 바꾸면 rules.md도 같이 고친다
- `wireframes/flow1~flow7.png`: 실제 화면 캡처 38개. 번호는 기획 번호(1~38)와 같다. AI 답 부분(무신사 상품, 계획 제안)만 예시

## 코드 반영 (가장 먼저 할 일)
이 zip의 패치는 아직 GitHub에 반영되지 않았다. 저장소 최신 상태에 따라 하나를 고른다.

1. `git pull` 후 `git log --oneline -3`으로 확인한다.
2. 맨 위가 438d8ca("feat: 설정 영역, 둘러보기, 되돌리기, 쓴 돈으로 적기, 캡처로 담기")라면:
   `patches/jigabi-shopchat.patch` → `patches/jigabi-plan.patch` 순서로 적용한다.
3. 5cee256("feat: 첫 설정 두 단계와 복구 코드 화면 UI…")에서 멈춰 있다면:
   `patches/jigabi-all.patch` 하나만 적용한다 (1번 수정부터 계획 도우미까지 전부).
4. 적용 전에 `git apply --check`로 먼저 확인한다. 둘 다 안 들어가면 억지로 고치지 말고 사용자에게 물어본다.
5. `pytest`가 111개 통과하면 패치마다 커밋하고 push한다 (CLAUDE.md 커밋 규칙). 패치 파일은 .gitignore에 걸려 있어서 커밋되지 않는다.
6. `HANDOFF.md`와 `wireframes/`는 저장소 `docs/`로 옮겨서 같이 커밋한다.
7. DB 표가 바뀌었으니 `docker compose down -v && docker compose up --build`.

## 코드 상태 (반영한 뒤)
- 테스트: `pytest`, 111개 통과. DB 테스트는 jigabi_test를 schema+seed로 새로 만든다
- AI는 `.env`의 `OPENAI_API_KEY`가 있을 때만 켜진다. `OPENAI_MODEL` 기본값은 gpt-5-mini(OpenAI가 '지원 중단 예정'으로 표시, 막히면 새 모델로 바꾼다). 키는 사용자가 `.env`에 직접 넣는다

## 화면 흐름 (38개)
1. 처음: [예시로 먼저 해 보기](예시 사람, 2026-10-31 고정, 저장 안 함), [내 걸로 시작하기]

7. 지갑이 채팅(AI): 계획 짜기, 무신사에서 찾기, 캡처로 담기

## AI 원칙
- 숫자는 앱(calc)이 계산하고, AI는 앱이 계산한 선택지 중에서 고르거나 칸을 채우기만 한다
- 저장은 사용자가 버튼을 눌러야 한다: [추가], [장바구니에 담기], [이대로 적용]
- 최소 생활비는 앱이 먼저 줄이지 않는다(R14). 끼니를 거르라는 제안은 하지 않는다(도시락으로 바꾸기만)
- 무신사 추천은 웹 검색에서 실제로 본 musinsa.com 페이지만 카드로 보여주고, 가격은 다시 확인하라고 알린다. 하루 20번까지

## 정해진 것 (바꾸지 않기)

- 무신사 사이트는 직접 긁지 않는다. OpenAI 웹 검색 + 도메인 필터만 쓴다
